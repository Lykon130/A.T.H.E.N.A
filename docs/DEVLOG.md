# Development Log

Seeded from the full development history (conversation-driven — most of this predates git being wired in, so this is richer than `git log` alone would show). `document-commit` appends one entry per commit going forward.

**Origin.** Project started from a JARVIS OS concept (voice → Claude Code → Obsidian vault → HUD, 4-part build), sourced from a set of reference slides. Initial build guide drafted, tailored to a Windows + Fedora dual-machine setup with Claude Code already installed.

**Reference synthesis.** Reviewed several other AI-assistant/business-OS reference builds: "Optimal Engine" (brain-store knowledge graph + Conductor routing + skill maturity ladder), "AI Headquarters" (department-dashboard concept), sagar_builds' "Ultron" (edge compute / gesture control / call-UI voice), "Council of High Intelligence" (multi-perspective deliberation), "AI Content Team OS" (research→hooks→scripts→design→publish→analyze pipeline), "One Claude, 11 Departments, 92 Skills" (an official skill taxonomy), and two AI trading/investing concepts.

**Merge and naming.** Decided to merge all references into one project rather than treat them as separate ideas. Named it A.T.H.E.N.A — Autonomous Tactical Hub for Execution, Networking & Analysis. Key architectural calls made at this stage: Claude Code doubles as engine and Conductor (no separate router needed); departments are skill groups, not standing agents (rejected the "8 independent AI workers" model as over-engineered for a one-person build); the Obsidian vault is the "brain-store" for free, no separate graph database.

**Initial scaffold.** `ARCHITECTURE.md` written. Vault structure (`raw/wiki/outputs`) and initial skills built: `vault-write`, `vault-health`, `inbox`, `metrics`, `plan`, `trends`.

**Cost model decision.** Confirmed Claude Code is included in the Claude Pro subscription, sharing one usage pool with Claude.ai chat and Cowork. Established the standing design rule: Claude is only called for reasoning/synthesis; all mechanical work (data pulls, polling, scanning) happens in plain scripts first. This is what keeps the growing skill count sustainable inside a Pro plan rather than requiring a from-scratch local-model build.

**Department expansion, round 1.** Added Legal and HR departments (taxonomy only, HR left empty — no employees). Added `finance/research-score`, modeled on an AI-investing reference, with the first hard boundary established: research and scoring only, never trade execution.

**News.** Added a News department: `news/global-scan` (GDELT — free, unlimited, no key) and `finance/news-monitor` (Finnhub free tier) for watchlist-specific alerts. Same hard boundary extended: monitoring/alerting only.

**Department expansion, round 2 — four focus areas.** User specified the actual scope: personal ops, solo business/freelance, content creation, investing/trading research. Built accordingly: `strategy/deliberate` (the Council pattern, at this point still Strategy-scoped) and `operations/calendar` for personal ops; `sales/pipeline-review`, `sales/draft-outreach`, `support/client-response`, `legal/review-contract` for solo business (draft-only boundary established for outreach/responses); `marketing/research`→`hooks`→`scripts`→`analyze` for content; `finance/portfolio-track`, `finance/watchlist-scan` for investing.

**JARVIS completionism.** User asked for the full JARVIS/Ultron feature set: memory, booking, and the Council pattern (already partially built). Added `vault/remember` + `vault/wiki/profile.md` (persistent user profile), a new Concierge department with `book-appointment`, and generalized `deliberate` into a cross-cutting `council` skill usable by any department, not just Strategy. Established the booking hard boundary: research/draft only, submission always needs per-instance confirmation, never handles payment/ID data.

**Parallel direct edits.** Several additions landed directly in the vault outside the conversation flow, in the same established pattern: `data/report` (cross-department weekly rollup), `concierge/plan-travel`, `design/ideate` (new Design department), `vault/digest` (proactive flagging, distinct from `report`'s full rollup).

**Health and Engineering.** Resolved the two remaining ambiguous departments: Health built as `health/log-health`, manual-entry based (the user's Noise wearable has no direct API, and its Google Fit bridge is being deprecated in 2026 in favor of Health Connect, which isn't remotely queryable — live sync deferred). Engineering built as `engineering/dev-digest` (GitHub/GitLab, read-only). Home/Environment left an intentional stub — a bare smart TV with no hub/app ecosystem was judged too thin to justify a department.

**Documentation automation.** User requested an on-every-commit documentation skill: system architecture, SRS, technical docs, code explanations, skill/module architecture, function-to-function call graphs, and a full development log. Split into `engineering/docs-init` (one-time full baseline) and `engineering/document-commit` (incremental, diff-scoped updates) to avoid regenerating everything on every commit, which would be slow and would burn Claude Pro's shared usage pool on a busy dev day. Documented the trigger tradeoff (post-commit vs. pre-push) and the need for scoped tool permissions on unattended headless runs.

**This baseline.** Discovered the repo was already git-initialized with a remote (`github.com/Lykon130/A.T.H.E.N.A`) and one prior commit. Applied `docs-init` to A.T.H.E.N.A itself as the first real target, adapted to current reality: no executable code exists yet, so `CODE_EXPLANATIONS.md` and `CALL_GRAPH.md` are stubs rather than fabricated content, `SKILLS_ARCHITECTURE.md` documents the routing/handoff model that does exist, and `SRS.md` reconstructs requirements from every decision made so far rather than being written speculatively upfront. Wired `.githooks/post-commit` for `document-commit` going forward (not yet activated — needs `git config core.hooksPath .githooks` run locally).
