# cffi is pinned to 1.17.1, not latest: on a Windows machine with Smart App
# Control enabled, the newest cffi wheel's compiled _cffi_backend*.pyd can get
# blocked (file too new to have Microsoft cloud-reputation yet — see
# CodeIntegrity event log, "did not meet Enterprise signing level
# requirements"). 1.17.1 has been out long enough to be broadly recognized.
# sounddevice and soundfile both need cffi; if a future pin still gets
# blocked, dropping to an older cffi release is the fix, not disabling Smart
# App Control.
cffi==1.17.1

# drop-in: it installs the same importable `webrtcvad` module without
# compiling anything, on Windows, Linux (Fedora), and Mac. capture.py uses it
# directly for utterance silence-detection.
