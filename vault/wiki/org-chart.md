# Org Chart

The department → skill map, kept live. Mirrors Optimal Engine's org-chart concept: every skill belongs to a department, every department has a maturity read.

| Department | Skills | Stage |
|---|---|---|
| Vault (cross-cutting) | vault-write, vault-health, remember | human-assisted |
| Cross-cutting | council (formerly Strategy's `deliberate`), digest | human-led / human-assisted |
| Operations | inbox, calendar | human-assisted / human-led |
| Finance | metrics, research-score, news-monitor, portfolio-track, watchlist-scan | human-led |
| News | global-scan | human-led |
| Strategy | plan, trends | human-led |
| Marketing | research, hooks, scripts, analyze | human-led |
| Sales | pipeline-review, draft-outreach | human-led |
| Support | client-response | human-led |
| Legal | review-contract | human-led |
| Concierge | book-appointment, plan-travel | human-led |
| Data | report | human-led |
| Design | ideate | human-led |
| Engineering | dev-digest, docs-init, document-commit | human-led / human-assisted |
| Health | log-health | human-led |
| Home/Environment | — | not built (smart TV only — too thin to justify a department; ask if TV on/off control specifically is wanted) |
| Human Resources | — | not built (no employees = no HR need yet) |

**Reference taxonomy** (from The Automation Guy's 92-skill/11-department marketplace) — not built, just naming conventions to borrow from when a department needs a real skill: Sales (`account-research`, `call-prep`, `draft-outreach`, `pipeline-review`), Finance (`financial-statements`, `reconciliation`, `sox-testing`, `variance-analysis`), Legal (`brief`, `compliance-check`, `review-contract`, `triage-nda`), Product Management (`metrics-review`, `sprint-planning`, `synthesize-research`, `write-spec`), Customer Support (`customer-escalation`, `draft-response`, `kb-article`, `ticket-triage`).

**Stages:** human-led (you trigger it, you review everything) → human-assisted (it runs on its own, flags things for you) → fully autonomous (it runs and acts without review).

Update this table whenever a skill's stage changes or a new one gets added — this is the one file that should always reflect reality.
