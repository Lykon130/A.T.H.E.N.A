---
name: voice-setup
department: engineering
stage: human-led
description: One-time setup for the local voice module — installs faster-whisper/Piper/openWakeWord/SpeechBrain dependencies, fetches STT/TTS/wake-word/speaker-verification models, runs voice enrollment, and writes voice/config.yaml. Run once per machine (Windows and Fedora both need it), or re-run to re-enroll or swap models.
---

Voice is wake-word-activated and speaker-verified: it only responds to the enrolled voice, and only after the wake word. This skill sets that up — it does not itself run the always-on listener (`python voice/listen.py` does that, after this completes).

**Speaker verification is a real security gate, not a convenience feature** — a false accept here means someone else's voice reaches Claude Code with no gate at all. An earlier build used resemblyzer's GE2E encoder and it produced a live false accept (an impostor scored *higher* similarity than the genuine owner); it was replaced with SpeechBrain's ECAPA-TDNN (`spkrec-ecapa-voxceleb`), a model actually built for speaker verification. Do not skip step 7's rejection test — an enrollment that only gets accept-tested is unverified.

1. **Install Python dependencies**: `pip install -r voice/requirements.txt` from the repo root, inside a venv (`voice/.venv`). `requirements.txt` pins `cffi==1.17.1` — on a Windows machine with Smart App Control enabled, newer `cffi` builds' compiled DLL can get blocked for lacking cloud reputation (`CodeIntegrity` event log shows "did not meet Enterprise signing level requirements"); if a future pin change re-triggers this, drop to an older `cffi` release rather than touching Smart App Control. `webrtcvad-wheels` provides the `webrtcvad` module import without needing MSVC build tools (the real `webrtcvad` PyPI package has no prebuilt Windows wheel).
2. **Faster-whisper model**: no separate download step — it fetches on first transcription. Confirm the configured `stt.model_size` in `voice/config.example.yaml` (default `small.en`) is reasonable for the machine (smaller model on lower-power hardware). If `faster-whisper`'s import of PyAV (`av`) fails with a Smart App Control / DLL-load error, `stt.py` already stubs it out — that dependency is only used for file-format decoding this module never needs.
3. **Piper voice model**: download a voice `.onnx` + `.onnx.json` pair into `voice/models/` from `rhasspy/piper-voices` on Hugging Face (`huggingface_hub.hf_hub_download`). Ask the user for a voice preference (e.g. male/female, accent) rather than assuming — this project currently uses `en_US-hfc_female-medium` after trying a few options live with the user.
4. **Wake word**: attempt to produce `voice/models/hey_athena.onnx` via openWakeWord's custom wake-word training flow (their training notebook generates synthetic "Hey Athena" clips and trains a small model from them — no real recordings of the user needed for this step). This is GPU-oriented and multi-hour; if it doesn't complete cleanly in one sitting, fall back to a pre-trained wake word (`openwakeword.utils.download_models()` fetches `hey_jarvis`, `hey_mycroft`, `hey_rhasspy`, `alexa`, etc., plus the `melspectrogram`/`embedding_model` feature extractors `Model()` needs by default — download to both `voice/models/` and the package's default resources dir, since download failures partway through are common and each location needs its own retry). Point `voice/config.yaml`'s `wake_word.model_path` at whichever landed, and tell the user "Hey Athena" training can be revisited later.
5. **Speaker verification model**: `EncoderClassifier.from_hparams(source="speechbrain/spkrec-ecapa-voxceleb", savedir="voice/models/ecapa", local_strategy=LocalStrategy.COPY)` — the `COPY` strategy is required on Windows since the default symlink strategy needs elevated privileges (`WinError 1314`). `verify.py` already does this.
6. **Write `voice/config.yaml`**: copy `voice/config.example.yaml` to `voice/config.yaml`, filling in the actual wake-word and Piper model filenames chosen above. List audio devices (`sounddevice.query_devices()`) and ask the user to confirm the mic/speaker if the default isn't correct.
7. **Enrollment**: run `python voice/enroll.py` interactively (the user speaks a few prompted phrases; must run with real mic access, not headlessly). It self-checks sample consistency and prints a suggested threshold range — set `speaker_verification.accept_threshold` in `voice/config.yaml` comfortably below the printed sample-to-voiceprint match minimum.
8. **Round-trip check — both directions**: run `python voice/listen.py`, have the user say the wake word plus a command, confirm a spoken reply comes back and an entry lands in `vault/raw/engineering/voice-sessions/<today>.md`. Then have a **different** person say the wake word plus a command and confirm it's silently rejected (check the printed similarity score — it should be well below threshold, not just barely). If the enrolled user's own genuine attempts sometimes score lower live than during enrollment (short/quiet utterances embed less reliably), that's normal — encourage a full sentence rather than a one-word command. Stop the process (Ctrl+C) once both cases are confirmed — this skill sets things up, it doesn't run the assistant continuously.

Never commit `voice/config.yaml`, `voice/voiceprint.npy`, `voice/models/`, or `voice/.session_id` — all gitignored (local paths, biometric data, and downloaded binaries).
